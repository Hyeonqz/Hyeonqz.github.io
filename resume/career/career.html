QR 결제 중계 플랫폼 구축 및 운영

간편결제사·POS·대형 가맹점 채널을 연결하고, 국내·해외 시스템 연동을 통해 은행 결제를 국내 가맹점까지 확장한 QR 결제 중계 서비스입니다.

핵심 성과 요약

  • 초기 공동 구축 이후 서버 개발·배포와 외부기관 연동을 단독으로 마무리해 첫 상용 오픈, 이후 일 평균 거래 50건 → 5,000건(100배) 성장 구간 무중단 운영
  • 국내외 결제사 7개사 중 5개사를 직접 연동하고 POS·대형 가맹점용 REST API 15종을 설계·구현해, 현재 전사 거래액의 80% 이상을 처리
  • 가맹점·대리점 온라인 접수 채널을 0→1 단독 구축해 누적 2만 건 이상 처리하고, 구형 POS 전용 DLL 연동으로 회사 월 거래액 10% 증가
  • Gemini·MySQL 용어 사전으로 KYC 영문명 수동 수정 95% 감소, 결제 상태 확정 API로 상태 불일치 CS 90% 감소, Outbox 적용 후 가맹 접수 파일 2만 건 이상 유실 0건 유지

기술스택

JavaSpring BootJPA MySQLRedisKafka NCPDocker

주요 역할 및 성과

  • 국내외 결제사 7개사 중 5개사를 직접 연동하고, POS·대형 가맹점용 REST API 15종 설계·구현
    • 연동 대상: 유니온페이·위챗페이·알리페이·라인페이 등 결제사, 세븐일레븐·이디야 등 대형 가맹점
    • HMAC 서명·API Key 인증을 적용하고, DB UNIQUE 제약으로 멱등성을 확보
  • 가맹점·대리점이 직접 접수하는 온라인 채널을 0→1 단독 구축해 누적 2만 건 이상 처리
    • 영업 계약 후 개발팀이 수기로 등록하던 절차를 가맹점·대리점의 온라인 입력 방식으로 전환하고, 접수 파일 생성부터 KYC 담당자 전달까지 자동화
    • DOCX 문서 업로드 → docx4j 기반 PDF 변환·저장·다운로드 흐름을 구현해 도입 예정이던 연 $999 라이선스 비용 제거
  • 구형 POS 전용 DLL 연동 모듈을 구축해 신규 QR 결제 채널을 확장하고 회사 월 거래액 10% 증가
    • HTTP·TCP 직접 연동을 지원하지 않고 전용 DLL만 호출하는 구형 POS 환경에 맞춰 C++ 네이티브 모듈 설계·개발
    • POS(C#) → DLL(C++) → 결제 서버(Java) 구조의 인터페이스와 서버 API를 직접 설계·구현
  • 결제 흐름을 직접 검증할 수 있는 테스트 웹을 단독 구축해 통합 테스트·검수 리드타임을 1개월 이상에서 2주로 단축
    • 개발자가 연동사와 일정을 맞춰 QR 이미지를 생성·전달하던 수동 검증 절차를, 연동사가 직접 QR을 생성·결제하는 셀프 테스트 방식으로 전환
    • 실제 POS와 동일한 결제 전 과정을 구현해 사내 개발·운영팀과 외부 결제사·가맹점이 사용

기술적 개선 사항

분산 환경에서 결제 결과 실시간 알림(Push) 기능을 신규 구축해 운영 중 중복 통지 0건 유지 [상세보기]

배경
  • 다중 TCP 서버 환경에서 단말 연결 정보인 Netty Channel이 연결을 수립한 인스턴스 메모리에만 존재
  • API 서버가 결제 단말의 연결을 보유한 TCP 서버를 식별할 수 없는 구조
해결
  • Kafka로 결제 결과를 TCP 서버에 fan-out하고, Redis의 단말기·Channel·서버 매핑을 조회해 연결을 보유한 서버에서만 Push
  • Push 실패 시 에러 코드에 따라 재시도하고, 단말이 결과를 수신하지 못한 거래는 배치에서 자동 취소해 미처리 거래 방지
결과
  • 운영 중 중복 Push 0건을 유지하고, API·TCP 서버 간 통신 분리로 알림 누락과 장애 전파 위험 통제

은행 결제의 국내 확장을 위한 국내·해외 결제 시스템 연동 — Kafka Request-Reply [상세보기]

배경
  • 해외 시스템에만 연동돼 있던 은행 간편결제를 국내 가맹점까지 확장해야 했음
  • 인프라 제약과 일정상 은행·국내 시스템의 직접 연동이 어려워, 자체 거래 원장과 상태를 관리하는 해외 시스템과 국내 시스템을 연결
해결
  • QR 생성·결제 검증·취소·환불은 Kafka Request-Reply로 처리하고, 결제 결과 통지는 단방향 Kafka 이벤트로 분리
  • 국내 시스템의 요구사항 분석과 ReplyingKafkaTemplate·CorrelationId 기반 Request-Reply 설계·구현·테스트·배포 담당
  • 해외 시스템 담당 개발자와 Topic·JSON Payload·Reply·15초 타임아웃 계약 협의
  • 거래번호를 Kafka Message Key와 멱등성 기준으로 사용하고, 국내 원장의 상태 전이 가능 여부를 검사해 중복·역순 이벤트 방어
  • EXPIRED 이후 늦은 성공은 취소 대기 상태로 전환하고, 10분 주기 배치에서 결제사 상태를 재확인해 취소 처리하며 취소 실패 시 최대 3회 재시도 후 Telegram으로 운영팀에 알림
트러블슈팅
  • 이중화 개발 환경에서 두 인스턴스가 동일 Consumer Group을 사용해 요청하지 않은 인스턴스가 Reply를 소비하고, 약 50%의 요청이 타임아웃되는 문제 발견
  • 네 가지 대안을 비교한 뒤 공유 Reply Topic과 인스턴스별 고유 Consumer Group으로 Reply를 fan-out하고, CorrelationId가 일치하는 요청을 보유한 인스턴스만 Future 완료
결과
  • 분산 환경에서 동시 요청·타임아웃·늦은 Reply·중복·역순 결과를 검증하고, 운영 약 2개월간 일 평균 약 500건을 처리하며 메시지 유실·15초 Reply 타임아웃 0건 유지

Gemini API·MySQL 용어 사전 기반 KYC 영문명 자동화로 수동 수정 95% 감소 [상세보기]

결제 상태 Polling에 Redis Cache-Aside를 도입해 반복 RDB 조회 최대 240회 제거 [상세보기]

Project 03  ·  2025.09 – 현재

모바일 POS 프로젝트

POS 단말 없이 가맹점 스마트폰에서 QR을 생성해 결제받는 모바일 POS 서비스를 3인 팀으로 구축했습니다.

기술스택

JavaSpring BootJenkins DockerNCP

주요 역할 및 성과

  • 3인 팀에서 결제·가맹점 연동 백엔드 개발의 50%를 담당해 목표보다 약 6주 앞서 출시하고, 등록 가맹점 1,000개 이상·회사 월 매출 5%에 기여
    • 외부 결제·가맹점 연동을 Adapter로 분리해 핵심 로직과 외부 기술 의존성 격리
    • Claude Code·Codex를 설계 검토·구현·테스트에 활용해 반복 작업과 검증 시간을 줄이고 조기 출시에 기여
  • Jenkins·Docker·NCP 기반 CI/CD 환경을 단독 설계·구축
    • 애플리케이션 빌드부터 컨테이너 배포까지의 파이프라인 구성

Project 04  ·  2025.08 – 2025.11

선불 충전·QR 결제 서비스 구축

사내 복지 포인트를 충전하고 기존 QR 결제망으로 사용할 수 있는 선불전자지급수단 서비스를 5인 팀으로 구축했으며, 현재 사내에서 운영 중입니다.

기술스택

JavaSpring BootJenkins DockerAWS

주요 역할 및 성과

  • 5인 팀에서 선불금 충전·가맹점 관리 백엔드 개발의 20% 담당
    • 복지 포인트 충전과 가맹점 QR 결제를 위한 API 설계·구현
    • 기존 QR 결제망과 연동해 간편결제 앱에서 선불 거래를 처리하도록 구성
  • 선불금 원장과 거래 기반 정산 리포트 구현
    • 충전·결제 거래 이력과 선불금 원장을 관리하고 정산 리포트를 생성하는 로직 개발
  • 금융당국 질의 대응과 심사 대상 시스템 개발에 참여해 선불전자지급수단 관련 심사 통과에 기여
    • 충전·결제·원장·가맹점 관리 흐름에 대한 질의 대응과 심사 자료 검증 지원
